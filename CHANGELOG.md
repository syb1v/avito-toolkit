# Changelog

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased]

## [0.29.1] - 2026-10-09

### Исправлено

- Итог ночного прогона показывал статус правки до применения («одобрено» вместо
  «применено») — сессия отчёта не обновляла объект после dry-run/live применения.


## [0.29.0] - 2026-10-09

### Добавлено

- **Авто-правки цен**: ночное задание (cron `REPRICE_AUTO_CRON`, 03:00 МСК)
  пересчитывает рекомендации и само меняет цены в кабинете продавца (шаг ≤5%,
  не ниже себестоимости; >10% — на подтверждение). Тумблер и режим
  dry-run/live — в панели на «Наших объявлениях», live включается двойной
  защитой (`SELLER_EDIT_MODE=live` + подтверждение).
- **AI-сводка к правкам**: один батч-вызов за ночь объясняет по каждому SKU,
  почему цена изменена; вывод — в карточке SKU и в итоге прогона.
- История правок и кнопки «Подтвердить/Отклонить/Применить/Откатить» переехали
  в карточки SKU; пункт «Правки» из меню убран, `/edits` редиректит на
  `/our-listings` (API правок сохранён).


## [0.28.0] - 2026-10-09

### Добавлено

- **«Мои объявления»** — кнопка у аккаунта: забирает свои объявления из профиля
  (`/profile/items`) через cookies аккаунта, кладёт в «Наши объявления» и сразу
  прогоняет матчинг. Парсер профиля не зависит от вёрстки выдачи (резюме и услуги
  без цены пропускаются), прогресс виден тостом, результат живёт в Redis 1 час.


## [0.27.1] - 2026-10-09

### Исправлено

- На сервере браузерный транспорт вообще не запускался: в образе жёстко
  `BROWSER_HEADLESS=false`, а X-сервера в контейнере нет. Теперь compose
  прокидывает `BROWSER_HEADLESS` из `.env` (на проде `true`) — загрузка cookies
  и браузерные обходы снова работают.


## [0.27.0] - 2026-10-09

### Изменено

- AI-модерация и скоринг работают **только по отфильтрованной выдаче поиска**:
  лишние модели (например, Beoplay HX/H100 в поиске Eleven) больше не тратят
  токены и не влияют на медианы. Учитываются include-группы, стоп-слова,
  регион, ручные скрытия и `max_age_days` — так же, как в аналитике.

## [0.18.0] - 2026-10-05

### Добавлено

- Watchdog в планировщике (каждые 5 минут): алерты **«воркер не отвечает»** и
  **«очередь забита»** с авто-закрытием при восстановлении; системные алерты
  (без search_id) видны на дашборде и в списке.
- Модальные окна для форм (поиск, аккаунт, cookies, прокси) и подтверждений
  (удаление, очистка) вместо системных `confirm()`.
- Всплывающие уведомления (тосты) с автоскрытием: обход в очереди, проверка
  аккаунта, cookies, роли, скрытие лота, очистка алертов, проверка прокси.
- Редактирование поиска модалкой **прямо на странице поиска** (без перехода
  на главную); форма поиска вынесена в общий компонент.
- Пагинация выдачи по 100 («Показать ещё»/«Назад») + лёгкий
  `GET /searches/{id}/listings/stats` для чипов/фильтра городов + скелетон
  загрузки (`loading.tsx`): крупный поиск 9.3 МБ/2.35 с → 131 КБ/0.68 с.
- Города/регионы по-русски везде: справочник расширен областями, краями,
  республиками; неизвестные слаги приводятся к читаемому виду.

### Изменено

- Счётчики очередей на дашборде теперь настоящие (stream `dramatiq:<q>.msgs` +
  отложенные `dramatiq:<q>.XQ`), а не всегда 0.
- UI-тексты переписаны человеческим языком (поиски, аккаунты, прокси, обход,
  алерты, мини-гайд с Cookie-Editor) — без технического жаргона.
- Проверка аккаунта показывает ход и результат (опрос до 2.5 минут), кулдаун —
  остатком минут.

### Исправлено

- 429 от HTTP-пробы прокси больше не помечается как «Авито блокирует»: это лимит
  для не-браузерных клиентов, браузер с cookies через тот же прокси работает;
  «живых» считаем по каналу, метка Авито — отдельно.
- Cookies-статус: `make cookies` отмечает основной аккаунт в БД; панель пишет
  «в профиле, проверены» вместо «не залиты».
- nginx в проде: динамический upstream через docker-DNS (`resolver 127.0.0.11`) —
  после пересоздания api/web больше нет 502.
- Воркер резолвит профиль аккаунта в `BROWSER_USER_DATA_DIR` (в проде
  `/data/browser-profile`), профиль не теряется.
- Удалён мёртвый код (`MASK_VISIBLE`, `new_profile_dir`), из документации убран
  IP старого прокси.

## [0.17.0] - 2026-10-03

  Авито, и что делать (личный IP или резидентные + sticky-привязка).

## [0.16.0] - 2026-10-03

### Добавлено

- Видимый статус «в очереди»: кнопка «Запустить обход» сразу показывает прогресс
  (очередь → подготовка → сбор), а не пустоту; планировщик тоже ставит метку.

  (None удаляет ключ), смена одного поля не сбрасывает keyword_groups/exclude и т.д.
- Пауза перед обходом сокращена (2–7 с) и видна как стадия «Подготовка».

## [0.15.2] - 2026-10-03

### Исправлено

- `SELECT DISTINCT ... ORDER BY` в матчинге (`match_our_listing`) валил
  `match-all` на PostgreSQL — кандидаты из активных поисков выбираются
  подзапросом, без DISTINCT.
- Алерты считаются только по матчам **внутри обходимого поиска**, а не по всем
  матчам SKU: раньше обход B&O/Devialet заново создавал алерт по iPhone-ски,
  помечая его чужим поиском (и он возвращался после удаления iPhone-поиска).
- Матчинг SKU отсекает варианты чужой модели/ёмкости (`Pro/Plus/Max/Mini/Ultra/SE`,
  256 ГБ ≠ 512 ГБ, другая серия), а авто-матчи лотов из удалённых поисков
  вычищаются — iPhone 15 больше не «сматчивается» с iPhone 15 Pro/512 ГБ.
  Подтверждённые/отклонённые оператором матчи не трогаются.

## [0.15.0] - 2026-10-03

### Добавлено

- Роли аккаунтов: `searcher` (обход выдачи) и `seller` (свои объявления, будущее
  массовое управление). Миграция 0009, выбор роли при создании в UI/CLI
  (`make account-add ... ROLE=seller`), переключение кнопкой, бейджи в панели.
  К поиску можно привязать только «поисковика» — API отвечает 422, воркер

- `scripts/dev.sh` + `make start/stop/restart/status`: поднимает весь локальный
  стек одной командой (Docker infra + API + планировщик + фронт в tmux), переживает
  закрытие терминала и перезагрузку. Логи в `/tmp/avito-*.log`.

### Исправлено

- Простой стека после перезагрузки Docker/машины: postgres/redis не поднимались
  (не было restart-политики), из-за чего воркер часами перезапускался без Redis,
  API/планировщик/фронт не были запущены, а UI показывал пустые поиски и «ничего
  не происходит» при запуске обхода. Теперь у postgres/redis/api/scheduler/web
  стоит `restart: unless-stopped`, а `make start` поднимает всё за один шаг.
- `make up-dev` больше не пересобирает образ воркера при каждом запуске (сборка
  могла виснуть на pip): пересборка вынесена в `make up-dev-build`.

- Сортировка выдачи: `?sort=position|price_asc|price_desc|new|status`, чипы в UI.
- Фильтры по городам: регион объявления парсится из URL (`listings.region`, миграция
  с бэкфиллом), include/exclude-города в параметрах поиска и чипы по топ-регионам
  в выдаче; «Город выдачи (slug)» подменяет регион в поисковом URL.
- Прозрачность причин: у каждого лота `exclude_reason` (manual/keyword/stopword/region),
  в сводке `region_excluded` и `manual_excluded`.
- Нулевые цены («0 ₽», «цена не указана») больше не попадают в статистику как 0.
- Анлимит обхода: `max_pages=0`/`CRAWL_MAX_PAGES_PER_RUN=0` — все страницы до пустой
  выдачи (со стопом по застою и CrawlGuard); выдача API без лимита (`limit=0`),
  в UI видно все объявления.
- Сводка: `stopword_excluded` — сколько лотов убрано стоп-словами (отдельно от
  include-фильтра); в выдаче у лотов флаг `excluded` и бейдж «фильтр».
- Документ `docs/accuracy.md` — честная оценка точности фильтров, AI-модерации
  и расчётов аналитики + способы проверки.

### Изменено

- Dev-воркер работает под UID/GID хоста (`HOST_UID`/`HOST_GID`) — файлы профилей
  больше не становятся root-овыми и `make cookies --fresh` не ломается.

  парсинга без БД и Redis.
- Тесты парсера, rate limiter (fakeredis) и гибридного транспорта — 32 теста.
