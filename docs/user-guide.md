# Инструкция по панели

Панель показывает всё, что собрала автоматика: конкурентов и цены, динамику,
свои SKU с матчингом, алерты и AI-дайджест. Интерфейс адаптирован под телефоны.

## Как открыть

- Локально из исходников: `docker compose up -d` → http://localhost:3000,
  API/Swagger — http://localhost:8000/docs.
- Локально без Docker: `docker compose up -d postgres redis`, затем
  `uvicorn` (backend) и `npm run dev` (frontend); воркер — `make worker-local`.

## Главная

Карточки сверху — быстрый пульс:

- **Поиски** — активные/всего. Поиск это URL выдачи (фильтры, название, профиль
  конкурента) + расписание cron.
- **Лотов на рынке** — активные объявления в базе.
- **Наши SKU** — сколько своих позиций ведётся.
- **Новые алерты** — сколько событий ждёт внимания.

Ниже — последние алерты (клик «К поиску») и список поисков. Импорт поисков пачкой:

```bash
make import-searches file=searches.json
# или POST /api/v1/searches/import
```

```json
[
  {"name": "iPhone 15 Москва", "url": "https://www.avito.ru/moskva/telefony?q=iphone+15", "schedule_cron": "*/30 * * * *"},
  {"name": "Конкурент", "url": "https://www.avito.ru/user/12345/profile"}
]
```

После импорта планировщик подхватит поиски в течение ~5 минут и начнёт обходы по cron.

## Страница поиска

- **Метрики активности**: активные, новые/снятые за сегодня, снятые за 7 дней,
  **вымывание** (снято/активные — прокси-спрос) и **срок жизни** снятых.
- **Цены рынка** (после IQR-отсечения выбросов): медиана, средняя, P25, P75,
  минимум, максимум и объём выборки.
- **Динамика цен** — график медианы/P25/P75 по дням (строится из дневных агрегатов).
- **Выдача** — текущие объявления с позицией, ценой и статусом (на телефоне —
  списком, на десктопе — таблицей).
- **Алерты** — сработавшие правила (например, «наша цена выше рынка»), кнопка
  «Принять» подтверждает алерт.
- **AI-дайджест** — кнопка «Сгенерировать»: LLM формирует сводку (цены, спрос,
  действия). Требует `DEEPSEEK_API_KEY`; без ключа честно вернёт подсказку.

## Наши объявления

- Добавление SKU: `POST /api/v1/our-listings/import` (JSON; цена принимается строкой
  «90 000 ₽») или перенос из спарсенного поиска/своего профиля:
  `POST /api/v1/our-listings/import-from-search/{id}`.
- **Рекомендации по ценам** — детерминированный расчёт для каждого SKU: стратегия
  (`Демпинг P25−1%`, `По медиане`, `Премиум P75`, `Держать цену`), целевая цена,
  дельта в процентах, флаг **нужно подтверждение** при изменении больше порога
  (по умолчанию 10%). Никогда не предлагает ниже себестоимости.
- Таблица/список SKU: наша цена, медиана рынка, дельта, число матчей, статус на Авито.
- Обновить матчи после новых обходов: `POST /api/v1/our-listings/match-all`
  (также запускается автоматически после каждого обхода).

Рекомендации пока информационные: массовое применение появится в фазе 6
(dry-run → подтверждение → применение → аудит → откат).

## Алерты

Правила создают события, например `price_above_market`: наша цена выше медианы рынка
больше чем на настроенный процент. Алерт можно принять (`ack`) в панели или через
`POST /api/v1/alerts/{id}/ack`. Повторные одинаковые алерты не дублируются.

## Что происходит автоматически

1. Планировщик по cron ставит обход каждого активного поиска.
2. Воркер собирает выдачу (браузер-first, при сбое — HTTP), пишет снапшоты при
   появлении лота и смене цены, помечает ушедшие.
3. Пересчитываются дневные агрегаты, обновляются матчи наших SKU, создаются алерты.
4. Ночью агрегаты пересчитываются ещё раз (JOB 01:10 UTC).

## Если что-то не работает

- Нет обходов — проверьте, что `worker` и `scheduler` запущены и поиск активен.
- Нет выдачи — смотрите [авторизацию](authorization.md): скорее всего нужен прогрев
  профиля или прокси.
- Нет рекомендаций — мало матчей: выполните `match-all` и убедитесь, что названия
  наших SKU похожи на рыночные.
- `npm run build` падает с `libsimdjson.so.33` — системное обновление сломало Node
  (нужна версия 33, установлена 34). Временный обход:

  ```bash
  mkdir -p /tmp/simdjson && ln -sf /usr/lib/libsimdjson.so.34 /tmp/simdjson/libsimdjson.so.33
  LD_LIBRARY_PATH=/tmp/simdjson npm run build
  ```

  Надёжное решение — переустановить Node или пакет `libsimdjson33` из репозитория
  дистрибутива.
- Ограничения и лимиты — раздел «Известные ограничения» в [README](../README.md).
