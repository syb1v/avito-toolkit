# Инструкция по панели

Панель показывает всё, что собрала автоматика: конкурентов и цены, динамику,
свои SKU с матчингом, алерты и AI-дайджест. Интерфейс адаптирован под телефоны.

## Как открыть

- Локально из исходников: `docker compose up -d` → http://localhost:3000,
  API/Swagger — http://localhost:8000/docs.
- Локально без Docker: `docker compose up -d postgres redis`, затем
  `uvicorn` (backend) и `npm run dev` (frontend); воркер — `make worker-local`.

## Быстрое наполнение реальными данными

1. **Поиски конкурентов** (фильтры, запросы, профили). Скопируйте шаблон и вставьте
   свои URL:

   ```bash
   cp searches.example.json searches.json   # отредактируйте под себя
   make import-searches file=searches.json
   ```

2. **Свои SKU** — любым из способов:
   - JSON: `cp skus.example.json skus.json`, заполните и загрузите:
     `make import-skus file=skus.json`;
   - из своего публичного профиля (соберёт объявления и перенесёт их):
     `make import-profile url="https://www.avito.ru/user/XXXX/profile"`
     (флаг `--activate` включит обход профиля по расписанию каждые 2 часа).

3. **Сопоставить с рынком и получить рекомендации:**

   ```bash
   curl -X POST localhost:8000/api/v1/our-listings/match-all
   ```

4. **Ручной обход конкретного поиска** (если не хотите ждать планировщик):

   ```bash
   curl -X POST localhost:8000/api/v1/searches/<id>/crawl
   ```

Файлы `searches.json` и `skus.json` — ваши реальные данные, они в `.gitignore`
и не попадают в репозиторий.

## Главная

Карточки сверху — быстрый пульс:

- **Поиски** — активные/всего. Поиск это URL выдачи (фильтры, название, профиль
  конкурента) + расписание cron.
- **Лотов на рынке** — активные объявления в базе.
- **Наши SKU** — сколько своих позиций ведётся.
- **Новые алерты** — сколько событий ждёт внимания.

Ниже — последние алерты (клик «К поиску») и список поисков. Импорт поисков пачкой:

```bash
make import-searches file=searches.json
# или POST /api/v1/searches/import
```

```json
[
  {"name": "iPhone 15 Москва", "url": "https://www.avito.ru/moskva/telefony?q=iphone+15", "schedule_cron": "*/30 * * * *"},
  {"name": "Конкурент", "url": "https://www.avito.ru/user/12345/profile"}
]
```

После импорта планировщик подхватит поиски в течение ~5 минут и начнёт обходы по cron.

## Страница поиска

- **Обход** — живой прогресс: статус, стадия (сбор страниц → аналитика → матчинг →
  алерты), номер страницы, найденные лоты, кнопка «Запустить обход» и время
  последнего сбора. Панель обновляется сама.
- **Метрики активности**: активные, новые/снятые за сегодня, снятые за 7 дней,
  **вымывание** (снято/активные — прокси-спрос) и **срок жизни** снятых.
- **Цены рынка** (после IQR-отсечения выбросов): медиана, средняя, P25, P75,
  минимум, максимум и объём выборки. P25 — четверть объявлений дешевле этой цены,
  P75 — четверть дороже; медиана — середина рынка.
- **Динамика цен** — график медианы/P25/P75 по дням (строится из дневных агрегатов).
- **Выдача** — текущие объявления с позицией, ценой и статусом (на телефоне —
  списком, на десктопе — таблицей).
- **Алерты** — сработавшие правила (например, «наша цена выше рынка»), кнопка
  «Принять» подтверждает алерт.
- **AI-дайджест** — кнопка «Сгенерировать»: LLM формирует сводку (цены, спрос,
  действия). Требует `DEEPSEEK_API_KEY`; без ключа честно вернёт подсказку.

## Наши объявления

- Добавление SKU: `POST /api/v1/our-listings/import` (JSON; цена принимается строкой
  «90 000 ₽») или перенос из спарсенного поиска/своего профиля:
  `POST /api/v1/our-listings/import-from-search/{id}`.
- **Рекомендации по ценам** — детерминированный расчёт для каждого SKU: стратегия
  (`Демпинг P25−1%`, `По медиане`, `Премиум P75`, `Держать цену`), целевая цена,
  дельта в процентах, флаг **нужно подтверждение** при изменении больше порога
  (по умолчанию 10%). Никогда не предлагает ниже себестоимости.
- Таблица/список SKU: наша цена, медиана рынка, дельта, число матчей, статус на Авито.
- Обновить матчи после новых обходов: `POST /api/v1/our-listings/match-all`
  (также запускается автоматически после каждого обхода).

Рекомендации пока информационные: массовое применение появится в фазе 6
(dry-run → подтверждение → применение → аудит → откат).

**Несколько аккаунтов продавцов.** У SKU есть метка `account`: передайте её при
импорте (`"account": "Магазин-1"` в JSON), в
`POST /our-listings/import-from-search/{id}?account=Магазин-1` или
`make import-profile url="..."` (флаг `--account`). Полное управление профилями,
прокси и сессиями по аккаунтам — в фазе 6.

## Умная фильтрация (AI-модерация)

Перед расчётом статистики выдача чистится от мусора — сначала бесплатными правилами,
затем дешёвым AI только по подозрительным. У флага есть **категория**:

| Категория | Что ловит | Пример |
|---|---|---|
| `copy` — копия/реплика | слова «копия», «реплика», «1:1», «аналог», «люкс» в названии или описании | «iPhone 15 копия 1:1, люкс качество» |
| `fake_bait` — приманка | цена ниже 35% медианы; фразы «цена не…», «предлагать цену», «розыгрыш» | «ТОРГ!! ПРЕДЛОГАТЬ ЦЕНУ ЦЕНА НЕ 6 ТЫСЯЧ» |
| `irrelevant` — нерелевант | запчасти, неисправности, «под восстановление», «не работает» | «Телефон… под восстановление, чипы WiFi» |
| `duplicate` — дубль | одинаковые «название + цена» у 5+ разных продавцов | массовые копии одного объявления |

Как это работает по шагам:

1. **Правила** по названию: стоп-слова, аномальная цена, дубли.
2. **Описания:** для кандидатов (флаг или цена ниже 60% медианы) догружаются страницы
   объявлений — до 10 за обход, с паузами 3–6 секунд. Описание хранится в базе и
   участвует в правилах (реплики, «под восстановление», приманки, контакты вне Авито).
   Кандидаты сортируются по подозрительности, уже загруженные не дублируются.
3. **AI-скоринг (DeepSeek):** батчами по 10, до 40 карточек за прогон — возвращает
   релевантность, категорию, уверенность и причину. Расход виден в `llm_runs`
   (задача `listing_moderation`).

В панели: чипы-фильтры над таблицей — **Все / Подозрительные (N) / приманка (N) /
копия-реплика (N) / нерелевант (N) / дубль (N)**; у карточки — цветной бейдж категории,
причины и сниппет описания. Статистика (медиана, P25/P75) считается **без**
отфильтрованных, в разделе цен есть строка «исключено N». Ручной прогон:
`POST /api/v1/searches/{id}/moderate` (без описаний) или
`backend/scripts/moderate_search.py --search-id <uuid>` (с описаниями).

Настройки в `.env`: `MODERATION_ENABLED`, `MODERATION_AI_ENABLED`,
`MODERATION_LOW_PRICE_RATIO`, `MODERATION_DUPLICATE_MIN_CLUSTER`,
`MODERATION_AI_BATCH_SIZE`, `MODERATION_MAX_AI_ITEMS`,
`MODERATION_DESCRIPTIONS_ENABLED`, `MODERATION_DESCRIPTION_MAX_ITEMS`,
`MODERATION_DESCRIPTION_DELAY_MIN_SECONDS`, `MODERATION_DESCRIPTION_DELAY_MAX_SECONDS`.

## Алерты

Правила создают события, например `price_above_market`: наша цена выше медианы рынка
больше чем на настроенный процент. Алерт можно принять (`ack`) в панели или через
`POST /api/v1/alerts/{id}/ack`. Повторные одинаковые алерты не дублируются.

## Что происходит автоматически

1. Планировщик по cron ставит обход каждого активного поиска.
2. Воркер собирает выдачу (браузер-first, при сбое — HTTP), пишет снапшоты при
   появлении лота и смене цены, помечает ушедшие.
3. Пересчитываются дневные агрегаты, обновляются матчи наших SKU, создаются алерты.
4. Ночью агрегаты пересчитываются ещё раз (JOB 01:10 UTC).

## Если что-то не работает

- Нет обходов — проверьте, что `worker` и `scheduler` запущены и поиск активен.
- Нет выдачи — смотрите [авторизацию](authorization.md): скорее всего нужен прогрев
  профиля или прокси.
- Нет рекомендаций — мало матчей: выполните `match-all` и убедитесь, что названия
  наших SKU похожи на рыночные.
- `npm run build` падает с `libsimdjson.so.33` — системное обновление сломало Node
  (нужна версия 33, установлена 34). Постоянный обход:

  ```bash
  mkdir -p ~/.local/lib/node-compat
  ln -sf /usr/lib/libsimdjson.so.34 ~/.local/lib/node-compat/libsimdjson.so.33
  LD_LIBRARY_PATH=~/.local/lib/node-compat npm run dev   # или npm run build
  ```

  Надёжное решение — переустановить Node или пакет `libsimdjson33` из репозитория
  дистрибутива.
- Ограничения и лимиты — раздел «Известные ограничения» в [README](../README.md).
