# Аккаунты Авито и загрузка cookies

Платформа умеет работать с несколькими аккаунтами: у каждого — свой профиль Chromium
со своими cookies. Поиск привязывается к аккаунту, и обход идёт под его сессией.
Основной профиль (`BROWSER_USER_DATA_DIR`) заведён миграцией как аккаунт «Основной»
и удалению не подлежит — им можно пользоваться как раньше.

## Роли аккаунтов

- **поисковик** (`searcher`, по умолчанию) — для обхода выдачи конкурентов. К поиску
  можно привязать только такие аккаунты.
- **продавец** (`seller`) — для управления своими объявлениями (свои SKU, репрайсинг,
  фаза массового управления). К поискам такие аккаунты не привязываются: API вернёт
  понятную ошибку, воркер пропустит обход с причиной «аккаунт продавца».

Роль переключается в UI кнопкой «Сделать продавцом/поисковиком» или через
`PATCH /api/v1/accounts/{id}` (`{"role": "seller"}`).

## TL;DR

```bash
make accounts                                            # список аккаунтов
make account-add name="Продавец 2" ROLE=seller           # создать профиль продавца
make account-add name="Поисковик 2"                      # создать поисковика
make account-cookies name="Продавец 2" BROWSER=brave     # залить cookies из Brave
make account-check name="Продавец 2"                     # проверить выдачу
```

В UI: панель **«Аккаунты»** на главной — кнопка «+ Добавить аккаунт» (имя, роль,
заметка), затем «Cookies» (вставить JSON Cookie-Editor или строку Cookie),
«Проверить», пауза, удаление, переключение роли. В форме поиска выбирается
аккаунт-поисковик.

## Почему это работает

Антибот-фаервол Авито доверяет связке «cookies + отпечаток браузера + история».
Ваш обычный браузер эту доверенность имеет, автоматизированный профиль — нет.
Поэтому cookies переносятся из браузера в профиль аккаунта: после этого поиск
отдаёт выдачу (проверка скрипта ждёт 50 объявлений и отсутствие челленджа).

## Способ 1: cookies из браузера на этой же машине (рекомендуется)

1. Войдите в нужный аккаунт Авито в Brave/Chrome — выдача должна открываться.
2. Закройте браузер (чтобы SQLite cookies не была занята).
3. Выполните:

```bash
make account-add name="Продавец 2"
make account-cookies name="Продавец 2" BROWSER=brave
# BROWSER=chrome|chromium|edge|firefox|librewolf|opera|vivaldi
```

Скрипт читает cookies через `browser-cookie3` (Linux: ключ из gnome-keyring/kwallet),
пишет их в `.accounts/<slug>` (в Docker — тот же каталог через bind-mount),
открывает видимый Chromium и проверяет выдачу. Cookies нигде не печатаются.

## Способ 2: вставить cookies в UI

1. Установите расширение **Cookie-Editor** в браузере, где Авито работает.
2. На `avito.ru` → Export → JSON (или DevTools → Application → Cookies → строка).
3. В панели «Аккаунты» нажмите **Cookies** у нужного аккаунта, вставьте JSON/строку,
   оставьте «сбросить старый профиль» и нажмите **Загрузить cookies**.

Задача уходит в воркер: он пишет cookies в профиль и проверяет выдачу. Статус
обновится в панели («ок»/ошибка) через несколько секунд.

## Способ 3: сервер без графики

На сервере нет вашего браузера и keyring. Схема: залейте cookies на машине с
браузером, затем перенесите каталог профиля:

```bash
# на ноутбуке
make account-add name="Продавец 2"
make account-cookies name="Продавец 2" BROWSER=brave
# скопировать профиль на сервер (пример для docker):
docker compose cp backend/.accounts/продавец-2/. worker:/data/.accounts/продавец-2
```

Для основного профиля то же самое: `docker compose cp backend/.browser-profile/. worker:/data/browser-profile`.
После переноса нажмите «Проверить» в панели.

## Прокси и аккаунты: почему датацентр не работает

Доверие Авито складывается из трёх вещей: **cookies + репутация IP + отпечаток
браузера**. «Чистый» (не из спам-листов) датацентр-прокси всё равно получает
`403 «Доступ ограничен: проблема с IP»`, потому что фаервол смотрит на **тип сети
(ASN)**: хостинг/датацентр = низкое доверие, домашний/мобильный ISP = высокое.
Cookies эту оценку не перебивают.

Проверено на этом стенде: прогретый профиль с личным IP → `200`, 50 объявлений;
тот же профиль через прокси `188.130.189.45` → `403 «проблема с IP»`; обратно
напрямую → снова `200`. То есть блокируется именно выходной IP, а не сессия.

Что делать:
- **Личный IP + прогретый аккаунт** — рабочий вариант, движок ходит напрямую
  (`PROXY_ENABLED=false`, аккаунту не назначен прокси).
- **Резидентные/мобильные прокси** (домашние ISP, желательно RU) — с ними поиск
  проходит. Закрепите один прокси за аккаунтом (sticky), чтобы cookies и IP
  не «прыгали»: UI «Аккаунты» → кнопка **Прокси** → выбрать из пула, или CLI
  `make account-proxy name="..." label="..."`.
- Датацентр-прокси (в том числе «чистые») для выдачи Авито не подходят — панель
  «Прокси» показывает по ним метку «Авито блокирует», это ожидаемо.
- Whitelist вашего IP у прокси-провайдера проблему не решает: Авито смотрит на
  репутацию самого прокси, а не на то, кто им пользуется.

## Привязка прокси к аккаунту (sticky)

- В панели «Аккаунты» нажмите **Прокси** у аккаунта и выберите прокси из
  `PROXY_LIST` (или «личный IP»). Хранится полный URL, в API/UI отдаётся только
  метка без пароля.
- Проверка аккаунта (кнопка «Проверить») выполняется не чаще раза в 10 минут
  (`ACCOUNT_CHECK_COOLDOWN_MINUTES`): API вернёт `status=cooldown` с остатком,
  CLI — `--force`, чтобы проверить принудительно. Это защита IP от самоизбиения.
- CLI: `make account-proxy name="Поисковик 2" label="http://user@host:5500"`,
  снять — `make account-proxy name="..."` (пустой label) или `--clear`.
- Воркер использует закреплённый прокси для этого аккаунта вместо общего пула;
  проверка аккаунта (`make account-check` / кнопка «Проверить») идёт через тот же
  прокси, так что статус отражает реальную связку cookies+IP.
- Один прокси ↔ один аккаунт. Если Avito начал отдавать челлендж — меняйте пару
  целиком (новый прокси + свежие cookies), а не по отдельности.

## Привязка к поискам и замок профиля

- В форме поиска («Изменить») выберите аккаунт. Если не выбирать — используется основной.
- Один профиль одновременно обходит только один поиск: в Redis ставится автозамок
  `crawl:account-lock:<id>` на 35 минут. Параллельный обход того же аккаунта будет
  пропущен с причиной «профиль занят другим обходом» (видно в панели обхода).
- Аккаунт на паузе не обходится: поиски с ним пропускаются до включения.

## Обслуживание

- **Протухли cookies** (челлендж вернулся): повторите `make account-cookies name=... --fresh`
  или залейте заново через UI. `--fresh`/галочка сбрасывает профиль, чтобы старые
  «сожжённые» cookies не тянулись за новыми.
- **Смена IP/прокси**: не смешивайте разные выходные IP у одного профиля — Авито
  привязывает доверие к связке. Для прокси-режима закрепите один прокси за аккаунтом.
- **Удаление**: неосновной аккаунт удаляется, поиски переводятся на основной.
  Каталог профиля остаётся на диске — удалите вручную, если он больше не нужен.
- **Права**: в dev-стеке воркер работает под вашим UID (`HOST_UID/HOST_GID`), файлы
  профиля принадлежат вам. В prod-образе воркер пишет в том `browserdata`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/accounts` | список аккаунтов и статусов |
| POST | `/api/v1/accounts` | создать аккаунт |
| PATCH | `/api/v1/accounts/{id}` | имя, заметки, пауза |
| DELETE | `/api/v1/accounts/{id}` | удалить (кроме основного) |
| POST | `/api/v1/accounts/{id}/cookies` | залить cookies (JSON/строка) |
| POST | `/api/v1/accounts/{id}/check` | проверить выдачу |
